# 「보통의 하루」 분석 × 하루메이트 기술 로드맵 (2026-09-06)

> **목적:** 서울시복지재단 「보통의 하루」를 공개 정보 기준으로 최대 해부하고, 하루메이트가 **구조적으로 앞서는 지점**과 **2026 SOTA AI로 더 벌릴 지점**을 기술 로드맵으로 고정한다.
> **원칙:** 기술은 당사자·보호자의 **편의**로 환원될 때만 채택한다. "있으면 멋진" 기술은 P3로 내린다.
> **정직성:** 「보통의 하루」는 보도자료 3건 + 협약 기사 2건만 공개. UI·계약금·기술 스택은 **미공개** → 추정은 "추정"으로 표기.

---

## 0. TL;DR

1. 「보통의 하루」 = **알람 3종(기상·복약·위생) + 사진/NFC 인증 해제**. 법무법인 계열(여온앤컴퍼니)이 후견·재산관리 사업의 부속 도구로 만든 것. 기획 출발점이 "지원인의 업무 효율"이라 **당사자 UX가 얇다.** 45명 기관 배포, 스토어 미출시, 11월 효과검증 예정.
2. 하루메이트가 이미 앞선 것: AI 일정 생성, 시각 일과표(지금|다음), 단계 카드+TTS, 메이트 대화, 보호자/당사자 모드, 스토어 배포 경로, Nemotron 페르소나 시뮬레이션. **부족한 것: 완료 인증(그들의 유일한 강점), 기관 이행률 검증 데이터.**
3. 벌릴 지점 4개: **① 온디바이스 멀티모달로 "사진 인증"을 넘어 "사진 이해"**(Gemini Nano / Apple Foundation Models / Gemma 3n), **② 보호자 목소리 프롬프트**(제로샷 음성 클로닝, 한국어), **③ 강화학습 리마인더 타이밍**(JITAI), **④ 웨어러블 스트레스 감지 → 개입 조절**(S-PACE 연구 자산 직결).
4. AGI-adjacent 프론티어 중 실제로 엮을 것: **영속 메모리 에이전트**(Mem0/Zep, 이미 v3에 있음 → 시간 추론 강화), **프로액티브 에이전트**(묻기 전에 다음 단계 준비), **실시간 카메라 어시스턴트**(Gemini Live/Astra 계열 → 요리 단계 실시간 코칭 = 온쿡 계보). 나머지(월드모델·범용 로봇)는 제외.
5. 순서: **P0 지금(2주) 완료 인증 옵션 + 이행률 로그** → **P1(1~2개월) 온디바이스 사진 이해 + 보호자 목소리** → **P2(3개월) JITAI + 웨어러블** → **P3(연구) 실시간 카메라 코칭**. 각 단계마다 완료율·오류·만족 3지표로 「보통의 하루」 11월 결과와 같은 언어로 비교 발표.

### 1.3 강점 / 약점 (우리 관점)

**강점 — 배워야 할 것**
- **행동 인증(사진/NFC)**: "알람을 봤다"가 아니라 "행동을 했다"를 기록 → 기관이 좋아하는 **검증 가능성**. 하루메이트에 없음.
- **공공 실증 경로**: 재단 사업 안에 들어가 45명 확보. 우리는 테스터 12명 모집 중.
- **극단적 단순성**: 기능 3개. 중증에게는 이게 맞을 수 있음.

**약점 — 우리가 벌릴 것**
- 고정 시각 알람 = **개인화 0**. 늦게 일어난 날 뒤 일정이 안 밀린다.
- **"다음에 뭐 하지"가 없음**: 알람과 알람 사이 공백 시간을 다루지 않음 (VAS 근거의 핵심을 놓침).
- 단계 안내 없음 → 위생 알람이 울려도 "어떻게"는 지원인 몫.
- 대화·정서 지원 0. 친구 없음 60.5%, 혼자 남겨짐 공포 33.4%에 무응답.
- 스토어 미출시 → 가족·개인 사용자 접근 불가. 우리는 Play 비공개 테스트 단계.
- NFC 태그는 물리 설치·분실 관리 비용. 사진 인증은 카메라 조작이 어려운 당사자에게 장벽.

| 축 | 보통의 하루 | 하루메이트 v1.5 | 격차 |
|---|---|---|---|
| 일정 생성 | 지원인이 고정 시각 입력 | 코디 자연어 → LLM 일정 생성 + 4그룹 템플릿 | ✅ 앞섬 |
| 시각 일과표 | 없음 | 지금\|다음 2칸 + 남은시간 링 + 오늘 타임라인(회색화) | ✅ 앞섬 |
| 단계 안내 | 없음 | 단계 카드 + TTS + 키오스크 single-focus | ✅ 앞섬 |

| 도움 요청 | 없음(추정) | 1탭 전화/문자/SOS + 감정 보드 | ✅ 앞섬 |
| 대화/정서 | 없음 | 메이트 에이전트 (Claude Haiku 4.5 / v3 멀티에이전트) | ✅ 앞섬 |
| 보호자 뷰 | 지원인 관리(추정) | 코디 홈 + 이행 현황 + B2B Streamlit | ≈ |
| 이행률 데이터 | **45명 5개월 축적** | 로컬 수행 기록만 | ❌ 뒤짐 → P0 |
| 인지접근성 설계 | 언급 없음 | Assistive Access 12원칙, 하단 고정 바, 타임아웃 0 | ✅ 앞섬 |

**결론:** 기능 폭·UX 깊이는 이미 우위. 뒤진 건 **"행동 인증"과 "실사용 데이터"** 두 개고, 둘 다 2주 안에 착수 가능.

## 3. 2026 SOTA 기술 지도 — 무엇이 어디에 쓰이나

### 3.1 온디바이스 멀티모달 (P1 핵심) — "사진 인증"을 "사진 이해"로

| 기술 | 상태 (2026-09) | 하루메이트 용도 | 제약 |
|---|---|---|---|
| **Gemini Nano + ML Kit GenAI Prompt API** (Android) | Pixel 10 출시 Gemini Nano 4, 이미지 이해(OCR·시각 추출) 강화. Prompt/Summarize/Image Description/Speech Recognition API. **온디바이스, 서버 비용 0, 오프라인** | ① 완료 인증: "이 사진에 칫솔·세면대가 보이나?" → yes/no + 한 줄 격려 ② 약 봉지 OCR → 복약 확인 ③ 단계 카드 자동 사진 캡션 | AICore 지원 기기 한정(Pixel·갤럭시 S 최신). `ondevice_llm.dart` 브리지 이미 존재, **Kotlin 어댑터 미작성** |
| **Apple Foundation Models** (iOS 26) | ~3B 온디바이스, **한국어 지원**, guided generation(구조화 출력), tool calling, 무료 | iOS 동일 기능. guided generation으로 `{done: bool, hint: str}` 스키마 강제 | iOS 26+ 기기. Flutter → Swift 플러그인 필요 |
| **Gemma 3n E2B** (LiteRT) | 텍스트·이미지·오디오 입력, 2B 메모리 풋프린트, 모바일 우선 | AICore 없는 안드로이드 폴백 | 앱 크기 +1~2GB, 발열. **선택 다운로드**로만 |
| **Qwen3.5-0.8B / MiniCPM-V** | 초경량 VLM | 저사양 기기 실험 | 한국어 품질 검증 필요 |

**설계:** 3-tier 캐스케이드 유지 — Tier 1 온디바이스(Nano/AFM) → Tier 2 백엔드(Gemini 2.x Flash 이미지) → Tier 0 NFC/탭. **사진은 기기 밖으로 안 나감**(판정 결과 bool + 해시 + 시각만 서버). 이게 「보통의 하루」 대비 **개인정보 우위** 포인트.

### 3.2 음성 — 보호자 목소리 프롬프트 (P1)

| 기술 | 상태 | 용도 |
|---|---|---|
| **OmniVoice** (k2-fsa, Apache-2.0, 2026-03) | 600+ 언어 제로샷 클로닝, 40× 실시간 | 부모 10초 녹음 → 모든 단계 안내를 부모 목소리로. 서버 배치 생성 → 기기 캐시 |
| **CosyVoice2 / Fish Speech 1.5 / IndexTTS-2** | 한국어 포함 크로스링구얼 클로닌 | 대안. 품질 A/B |
| **Kokoro** (82M) | 한국어 지원, CPU 실시간, MOS 4.2 | 기본 TTS를 Edge TTS에서 자체 호스팅으로 교체 → Render 의존 제거 |

**근거:** Visual Schedule Planner의 "보호자 오디오 커스텀"이 유료 차별점. 발달장애 아동·성인에게 **익숙한 목소리**는 지시 수용도를 높인다(임상 상식, 정량 근거는 우리가 만들 것). **동의·철회 UI 필수**, 목소리 데이터는 기기 내 저장.

### 3.3 리마인더 타이밍 — JITAI 강화학습 (P2)

| 기술 | 상태 | 용도 |
|---|---|---|
| **JITAI + RL** (Annual Review of Psychology 2026; AdaptRL NCT05751993; 스마트폰 운동 알림 RL 4주 실증) | mHealth에서 컨텍스트(시간·요일·응답 이력) 기반 알림 시점 최적화가 표준화 단계 | "알람 5분 전이 좋은 사람 / 정각이 좋은 사람"을 **밴딧**으로 학습. 응답 지연·스킵을 보상 신호로 |
| 구현 | Thompson Sampling 밴딧(온디바이스, 수십 줄) → 충분한 데이터 후 contextual | 서버 불필요. 개인별 3~4개 arm(−10/−5/0/+5분) |

**「보통의 하루」 고정 시각 알람과의 결정적 차이.** 늦게 일어난 날 뒤 일정 자동 재배치(schedule shift)도 여기 포함.

### 3.4 웨어러블 스트레스 감지 → 개입 조절 (P2, **JY 연구 직결**)

| 기술 | 상태 | 용도 |
|---|---|---|
| HRV/EDA 기반 스트레스 감지 (Sensors 2024 ASD 체계적 문헌고찰; 2026 arXiv 교실 내 도전행동 예측) | 웨어러블 생체신호로 ASD 스트레스 에피소드 예측 연구 활발. **감각 민감성 때문에 착용 거부 이슈** | 스마트워치(Wear OS/Watch) HRV 하락 → ① 단계 카드 속도 늦추기 ② "기다리는 중" 화면 자동 제안 ③ 보호자 알림(옵트인) |

### 3.5 에이전트 메모리 · 프로액티브 (AGI-adjacent, v3 강화)

| 기술 | 상태 (2026) | 용도 |
|---|---|---|
| **영속 메모리** — Mem0 State of Agent Memory 2026, AgeMem(메모리 연산을 도구로), Membox(토픽 박스+타임라인), MAGMA(의미·시간·인과·개체 4그래프) | "시간 추론"이 열린 과제 | v3 `mem_store.py` 3-tier에 **temporal validity + 인과 링크** 추가: "지난주 산책 3번 스킵 → 비 오는 날" 패턴 → 보호자 리포트 |
| **프로액티브 에이전트** ("Remember When It Matters", Always-On Agents 서베이 2026) | 반응형 → 능동형 전환이 2026 핫 토픽 | 메이트가 **묻기 전에** 다음 단계 준비: 산책 15분 전 날씨 확인 → "우산 챙기자" 카드 자동 생성 |
| **Claude Agent SDK / MCP** | 도구 호출 표준 | 백엔드 v3 오케스트레이터를 MCP 서버화 → 복지관 대시보드·캘린더·알림 도구 플러그인 |

### 3.6 실시간 카메라 코칭 (P3, 연구 트랙 — 온쿡 계보)

| 기술 | 상태 | 용도 |
|---|---|---|
| **Gemini Live 카메라 모드 (Project Astra)** — Android 10+ 전 기기, 실시간 영상+음성 | 상용 배포됨(구독). 개발자 API는 Live API로 접근 | "지금 프라이팬 보여줘" → "불 줄여, 뒤집을 때야". **온쿡 요리 클래스의 앱 버전.** |
| 제약 | 구독/비용, 지연, 안전(화기) | 보호자 동석 모드로만 시작. 논문·시연용 |

### 3.7 채택하지 않는 것 (명시)

- 월드모델·범용 로봇·AGI 벤치마크 류: 당사자 편의로 환원 불가.
- 게이미피케이션 포인트/스티커: 근거 약하고 성인 당사자 존중 이슈.
- 얼굴 인식 기반 인증: 개인정보·오인식 위험. 행동 인증은 사물/장면 판정으로 충분.
